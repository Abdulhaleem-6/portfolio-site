# Recruiter-friendly case-study copy design

## Audience and goal

Rewrite the four Selected Work case studies for technical recruiters, product managers, and hiring managers. Each case should explain the user or business problem first, describe Abdulhaleem's contribution in plain English, and connect technical decisions to practical outcomes.

## Scope

Update the reader-facing narrative in the four case-study content files: titles, hooks, summaries, roles, context, constraints, diagram captions, hard-part explanations, excerpt notes, decision copy, outcome labels, and retrospective notes.

Keep the underlying facts unchanged. Preserve periods, status, stack entries, repository links, metrics, metric evidence, architecture relationships, and code excerpts.

## Voice and structure

- Use active first-person language for Abdulhaleem's work.
- Use collaborative role descriptions where the source shows shared ownership.
- Lead with the practical problem and the people or business process affected.
- Explain technical terms only when they clarify the value of the solution.
- Keep sentences short and use measured language.
- Retain numbers, then explain why they matter.
- Remove em dashes and the banned terms: seamlessly, robust, meticulously, delve, testament to, merely, revolutionary, and cutting-edge.

Each case should follow this arc:

1. The practical problem.
2. Abdulhaleem's contribution and collaboration context.
3. How the solution works in plain language.
4. The measurable result or operating scale.
5. What Abdulhaleem would improve next.

## Verification

Search all four files for banned words and em dashes. Review the diff to ensure no metrics, evidence, stack entries, links, or code excerpts changed. Run the project's type check and production build.
